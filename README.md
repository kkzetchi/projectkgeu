# RAG-ассистент по документу

Интеллектуальная система вопросов и ответов по загруженному документу на основе подхода **Retrieval-Augmented Generation (RAG)**. Система читает текстовый файл (PDF, DOCX, TXT, MD) и отвечает на вопросы строго по его содержанию — без выдумывания фактов и без обращения к внешним знаниям.

## О проекте

Классические языковые модели отвечают на вопросы, опираясь на свои обучающие данные — это приводит к галлюцинациям, когда речь идёт о специфических документах (инструкции, отчёты, научные статьи, договоры). RAG решает эту проблему: система сначала **находит** в документе фрагменты, релевантные вопросу, а затем **формулирует** ответ, используя только эти фрагменты как источник истины.

**Что умеет система:**

- Загружать документы в форматах `.pdf`, `.docx`, `.txt`, `.md`
- Отвечать на вопросы по содержанию документа на естественном языке
- Честно признаваться, если ответа в документе нет
- Работать в интерактивном диалоговом режиме прямо в Google Colab
- Проходить автоматическое тестирование по эталонным вопросам

**Ключевые особенности:**

- Работает полностью локально — данные документа не отправляются в облачные API
- Умещается на бесплатный GPU Google Colab (T4, 16 ГБ)
- Соблюдает инструкции: не выдумывает факты, цитирует, отказывается отвечать при отсутствии информации
- Поддерживает русский и английский языки

## Как это работает

```
┌─────────────────────────┐
│ Вопрос пользователя     │
└────────────┬────────────┘
             ▼
┌─────────────────────────────────────────────┐
│ multilingual-e5-base (эмбеддер)             │
│ Кодирует вопрос в вектор (768 чисел)        │
└────────────┬────────────────────────────────┘
             ▼
┌─────────────────────────────────────────────┐
│ Поиск по косинусной близости                │
│ Находит top-k ближайших фрагментов          │
│ документа                                   │
└────────────┬────────────────────────────────┘
             ▼
┌─────────────────────────────────────────────┐
│ Qwen2.5-1.5B-Instruct (answerer)            │
│ Формулирует ответ по найденным фрагментам   │
└────────────┬────────────────────────────────┘
             ▼
┌─────────────────────────┐
│ Ответ пользователю      │
└─────────────────────────┘
```

**Пайплайн в деталях:**

1. **Индексация.** Документ разбивается на перекрывающиеся фрагменты (`chunk_size=500`, `overlap=100`). Каждый фрагмент кодируется эмбеддером в вектор и сохраняется в памяти.
2. **Поиск.** Вопрос пользователя кодируется тем же эмбеддером. По косинусной близости находятся `top_k=3` наиболее похожих фрагмента.
3. **Генерация.** Найденные фрагменты вместе с вопросом и системной инструкцией подаются в языковую модель. Модель формулирует ответ, опираясь только на предоставленный контекст.

## Используемые модели

### 1. Эмбеддер: [`intfloat/multilingual-e5-base`](https://huggingface.co/intfloat/multilingual-e5-base)

Модель семейства E5 для преобразования текста в векторные представления. Поддерживает более 100 языков, включая русский.

| Параметр | Значение |
|---|---|
| Размерность вектора | 768 |
| Максимальная длина | 512 токенов |
| Параметров | 278 млн |
| Размер в памяти | ~1 ГБ |

Требует префиксов `passage:` (для документов) и `query:` (для запросов). Без них качество поиска снижается.

### 2. Answerer: [`Qwen/Qwen2.5-1.5B-Instruct`](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct)

Инструктивно-обученная языковая модель от Alibaba (сентябрь 2024). Хорошо следует инструкциям, уверенно работает на русском.

| Параметр | Значение |
|---|---|
| Параметров | 1.5 млрд |
| Контекстное окно | 33K токенов |
| Размер в памяти (fp16) | ~3 ГБ |
| Лицензия | Apache 2.0 |

Модель получает вопрос и найденные фрагменты и формулирует ответ. Системная инструкция ограничивает её: использовать только информацию из контекста, не выдумывать, при отсутствии ответа — отказаться.

## Установка и запуск

### Требования

- Google-аккаунт для доступа к Google Colab
- Включённый GPU: `Runtime` → `Change runtime type` → `T4 GPU`

### Пошаговый запуск

1. Откройте ноутбук `RAG_Assistant.ipynb` в Google Colab.
2. Установите зависимости:
   ```bash
   !pip install "transformers>=4.42.0" accelerate sentence-transformers pypdf python-docx
   ```
3. Запустите ячейку с загрузкой моделей (первый запуск занимает 2–4 минуты — модели скачиваются с Hugging Face).
4. Запустите ячейку с определением класса `RAGAssistant`.
5. Загрузите свой документ через `files.upload()`.
6. Общайтесь с ассистентом в интерактивном режиме.

### Локальная установка (без Colab)

```bash
git clone https://github.com/your-username/rag-assistant.git
cd rag-assistant
pip install -r requirements.txt
jupyter notebook RAG_Assistant.ipynb
```

Требуется GPU с объёмом памяти ≥ 8 ГБ для комфортной работы.

## Пример использования

После загрузки документа просто задавайте вопросы:

```
Вы: Какова максимальная глубина озера по данным экспедиции 1987 года?
Ассистент: 33,4 метра

Вы: Сравните максимальные глубины, зафиксированные в 1912 и 1987 годах.
     На сколько метров они различаются?
Ассистент: В 1912 году — 28 метров. В 1987 году — 33,4 метра.
           Разница: 33,4 − 28 = 5,4 метра.

Вы: Какие землетрясения происходили в районе озера за последние сто лет?
Ассистент: В загруженном тексте этого нет.
```

Для отладки доступен режим с показом найденных фрагментов:

```python
answer = rag.ask("Ваш вопрос", verbose=True)
```

Вывод:
```
[Поиск] Найденные фрагменты:
  [0.867] ну 28 метров. В 1959 году экспедиция Московского...
  [0.852] одного зеркала составляет 12,4 гектара, максимальная глубина — 33,4 метра...
  [0.818] мках экспедиции и требуют дополнительного изучения...
```

Число в квадратных скобках — косинусная близость фрагмента к вопросу (чем выше, тем релевантнее).

### Основные компоненты класса `RAGAssistant`

| Метод | Назначение |
|---|---|
| `load_text()` | Разбивает текст на фрагменты и кодирует их эмбеддером |
| `load_file()` | Загружает файл (PDF, DOCX, TXT, MD) и вызывает `load_text()` |
| `_retrieve()` | Находит top-k релевантных фрагментов по косинусной близости |
| `ask()` | Основной метод: поиск + генерация ответа |

## Результаты тестирования

Система проверялась на документе «Отчёт о гидрологической экспедиции на озеро Светлояр» (8 вопросов, 4 категории сложности).

| Категория | Вопросов | Результат | Комментарий |
|---|---|---|---|
| A. Прямые факты | 2 | 2/2 | Точное извлечение чисел и дат |
| B. Синтез | 2 | 2/2 | Сравнение, арифметика, агрегация |
| C. Аномалии | 2 | 2/2 | Не выдумывает объяснений при нерешённых вопросах |
| D. Ловушки | 2 | 2/2 | Корректно отказывается отвечать |
| **Итого** | **8** | **8/8** | **100% точность** |

Среднее время ответа: **~2.5 секунды** на GPU T4.

### Примеры корректных ответов

**Прямой факт (A1):**
> *Вопрос:* Какова максимальная глубина озера по данным экспедиции 1987 года?
> *Ответ:* 33,4 метра

**Синтез + арифметика (B1):**
> *Вопрос:* Сравните максимальные глубины в 1912 и 1987 годах.
> *Ответ:* В 1912 году — 28 метров. В 1987 году — 33,4 метра. Разница: 33,4 − 28 = 5,4 метра.

**Отказ при отсутствии информации (D1):**
> *Вопрос:* Кто финансировал экспедицию 1987 года?
> *Ответ:* В загруженном тексте этого нет.

## Возможные улучшения

- **Реранкер (`BAAI/bge-reranker-v2-m3`).** Cross-encoder для пересортировки top-10 кандидатов и отбора действительно релевантных фрагментов. Улучшает точность поиска, но добавляет ~1 секунду на запрос.
- **Более крупная LLM.** `Qwen/Qwen2.5-3B-Instruct` или `7B` в 4-битной квантизации. Улучшает синтез, но требует больше памяти.
- **FAISS или Chroma.** Замена numpy-поиска на специализированную векторную базу данных для работы с тысячами фрагментов.
- **Голосовой ввод/вывод.** Интеграция с Whisper (ASR) и Silero TTS для полноценного голосового диалога.
- **Мультидокументный режим.** Возможность загружать несколько файлов и искать ответы по всем сразу.
- **Query Rewriter на 1.5B.** Для переформулировки разговорных вопросов в поисковые запросы (для маленьких моделей требуется few-shot промпт).
